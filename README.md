## Как запустить

### 1\. Клонируем репозиторий

```bash
git clone https://github.com/code-sisters-home/community-website.git
```

### 2\. Переходим в директорию

```
cd community-website
```

### 3\. Устанавливаем зависимости

```
npm install
```

### 5\. Запускаем dev-сервер

```
npm run dev
```

### 6\. Запустить линтер перед тем, как сделать коммит и запушить

```
npm run lint
```

# Тестирование

## Тесты компонента Navbar

### Общее описание

Данные тесты проверяют функциональность компонента **Navbar** (Навигационная панель), который обеспечивает навигацию по сайту, включает переключение тем и адаптивное мобильное меню.

---

### Что тестируют эти тесты

#### 1. Рендеринг и структура

**`renders the logo correctly`**
- **Проверяет:** Корректное отображение логотипа "code_sisters" с фигурными скобками
- **Зачем:** Убедиться, что брендинг отображается правильно
- **Метод:** Поиск текстовых элементов логотипа в DOM

**`renders all navigation items`**
- **Проверяет:** Отображение всех пунктов навигационного меню (Главная, О нас, ЧаВо, Блог, Мерч)
- **Зачем:** Гарантировать, что все основные разделы сайта доступны для навигации
- **Метод:** Поиск каждого пункта меню и проверка их наличия (как в десктопной, так и в мобильной версии)

**`renders ThemeChanger component`**
- **Проверяет:** Наличие компонента для переключения темы
- **Зачем:** Убедиться, что функционал смены темы доступен пользователю
- **Метод:** Поиск по `data-testid="theme-changer"`

**`renders mobile menu toggle button`**
- **Проверяет:** Наличие кнопки-гамбургера для открытия мобильного меню
- **Зачем:** Обеспечение доступности мобильной навигации
- **Метод:** Поиск кнопки по `aria-label="Toggle Menu"`

---

#### 2. Переключение темы (ThemeChanger)

**`toggles theme when clicked`**
- **Проверяет:** Переключение между светлой и темной темой при клике
- **Зачем:** Ключевая функциональность для пользовательского опыта
- **Метод:**
  - Проверка начального состояния (светлая тема)
  - Клик - проверка переключения на темную тему
  - Повторный клик - проверка возврата к светлой теме
  - Проверка атрибутов, текста и CSS-классов

**`toggles dark class on document element`**
- **Проверяет:** Добавление/удаление класса `dark` на элементе `<html>`
- **Зачем:** Обеспечение правильного применения стилей для темной темы
- **Метод:** Проверка наличия/отсутствия класса `dark` на `document.documentElement` после переключения

---

#### 3. Внешние ссылки

**`renders external merch link with correct attributes`**
- **Проверяет:** Корректное отображение внешней ссылки на магазин мерча
- **Зачем:** Безопасность и правильное поведение при открытии внешних ссылок
- **Метод:** Проверка атрибутов `href`, `target="_blank"` и `rel="noopener noreferrer"`

---

#### 4. Мобильное меню

**`mobile menu is hidden by default`**
- **Проверяет:** Мобильное меню скрыто при загрузке страницы
- **Зачем:** Улучшение пользовательского опыта - меню не должно быть открыто по умолчанию
- **Метод:** Проверка наличия класса `lg:hidden` у мобильного меню

**`toggles mobile menu when hamburger button is clicked`**
- **Проверяет:** Открытие и закрытие мобильного меню при клике на кнопку-гамбургер
- **Зачем:** Базовая функциональность мобильной навигации
- **Метод:**
  - Клик для открытия - проверка, что меню видимо
  - Повторный клик для закрытия - проверка, что меню скрыто

**`renders all navigation items in mobile menu when open`**
- **Проверяет:** Отображение всех пунктов навигации в открытом мобильном меню
- **Зачем:** Убедиться, что все ссылки доступны в мобильной версии
- **Метод:** Поиск всех пунктов меню внутри контейнера мобильного меню с использованием `within()`

---

#### 5. Навигация

**`internal links have correct href attributes`**
- **Проверяет:** Правильные URL-адреса для внутренних ссылок
- **Зачем:** Обеспечение корректной навигации по сайту
- **Метод:** Проверка атрибута `href` у каждой ссылки на соответствие ожидаемым путям (`/`, `/about`, `/faq`, `/blog`)

---

### Технические детали

- **Библиотеки:** React Testing Library, Vitest, @testing-library/jest-dom
- **Мокание:**
  - `next/navigation` - для мока `usePathname`
  - `next/link` - для мока компонента Link
  - `DarkSwitch` - для контроля состояния темы
  - `MenuIcon` - для мока иконки меню
- **Работа с DOM:** Прямые манипуляции с `document.documentElement` для тестирования классов темы
- **Асинхронность:** Использование `fireEvent` для симуляции событий
- **Очистка:** Удаление класса `dark` между тестами для изоляции

## Тесты компонента Gallery

### Общее описание

Данные тесты проверяют функциональность компонента **Gallery** (Галерея), который реализует карусель для отображения элементов с пагинацией и навигационными кнопками.

---

### Что тестируют эти тесты

#### 1. Рендеринг и структура

**`should render all items`**
- **Проверяет:** Отображение всех переданных элементов галереи
- **Зачем:** Убедиться, что все элементы корректно рендерятся внутри галереи
- **Метод:** Проверка наличия каждого элемента по его текстовому содержимому

**`should render navigation buttons`**
- **Проверяет:** Наличие кнопок навигации (< и >)
- **Зачем:** Гарантировать, что пользователь может перемещаться между страницами
- **Метод:** Поиск кнопок с символами "<" и ">"

**`should disable prev button on first page`**
- **Проверяет:** Кнопка "Назад" отключена на первой странице
- **Зачем:** Предотвращение навигации до первой страницы
- **Метод:**
  - Проверка атрибута `disabled`
  - Проверка классов (`opacity-30`, `cursor-not-allowed`)
  - Проверка стилей (`transform: scaleY(3)`)

**`should disable next button on last page`**
- **Проверяет:** Кнопка "Вперед" отключается на последней странице
- **Зачем:** Предотвращение навигации после последней страницы
- **Метод:**
  - Проверка начального состояния (активна)
  - Навигация на последнюю страницу
  - Проверка состояния `disabled`, классов и стилей

---

#### 2. Навигация вперед

**`should navigate to next page when Next button is clicked`**
- **Проверяет:** Переход на следующую страницу при клике на кнопку ">"
- **Зачем:** Основная функциональность навигации по галерее
- **Метод:**
  - Проверка начальной позиции (`translateX(0%)`)
  - Клик по кнопке "Вперед"
  - Проверка изменения трансформации на `translateX(-100%)`
  - Проверка вызова `onNext` колбэка

---

#### 3. Навигация назад

**`should navigate to previous page when Prev button is clicked`**
- **Проверяет:** Переход на предыдущую страницу при клике на кнопку "<"
- **Зачем:** Возможность возврата к предыдущим элементам
- **Метод:**
  - Навигация на вторую страницу
  - Клик по кнопке "Назад"
  - Проверка возврата на первую страницу (`translateX(0%)`)
  - Проверка вызова `onPrev` колбэка

**`should navigate multiple pages backward`**
- **Проверяет:** Навигацию назад на несколько страниц
- **Зачем:** Убедиться, что работает последовательный переход по страницам
- **Метод:**
  - Переход на последнюю страницу (200%)
  - Два клика "Назад"
  - Проверка промежуточного (-100%) и конечного (0%) состояний
  - Проверка количества вызовов `onPrev`

**`should not navigate before first page`**
- **Проверяет:** Невозможность перейти на страницу до первой
- **Зачем:** Безопасность навигации - защита от выхода за границы
- **Метод:**
  - Проверка, что кнопка "Назад" отключена на первой странице
  - Попытка клика на отключенную кнопку
  - Проверка, что позиция не изменилась
  - Проверка, что `onPrev` не был вызван

---

#### 4. Граничные случаи

**`should handle empty items array`**
- **Проверяет:** Поведение компонента с пустым массивом элементов
- **Зачем:** Устойчивость к пустым данным
- **Метод:**
  - Проверка, что контейнер не содержит дочерних элементов
  - Проверка, что обе кнопки навигации отключены

**`should handle single item`**
- **Проверяет:** Поведение с одним элементом в галерее
- **Зачем:** Обработка минимального количества элементов
- **Метод:**
  - Проверка отображения единственного элемента
  - Проверка, что обе кнопки навигации отключены

**`should handle itemsPerPage greater than items length`**
- **Проверяет:** Ситуацию, когда элементов меньше, чем элементов на страницу
- **Зачем:** Корректное поведение при нестандартных параметрах
- **Метод:**
  - Создание галереи с 2 элементами и 5 элементами на страницу
  - Проверка, что обе кнопки навигации отключены

---

### Технические детали

- **Библиотеки:** React Testing Library, Vitest
- **Мокание:**
  - `offsetWidth` для имитации размеров контейнера
  - Колбэки (`mockUpdateItemsPerPage`, `mockOnNext`, `mockOnPrev`)
- **Структура данных:** Использование интерфейса `GalleryItem` с полями `id` и `content`
- **Анимации:** Проверка CSS-трансформаций (`translateX`) для слайдов
- **Состояния:** Тестирование отключенных состояний кнопок
- **Очистка:** Сброс моков между тестами через `beforeEach` и `afterEach`

## Тесты компонента Footer

### Общее описание

Данные тесты проверяют функциональность компонента **Footer** (Подвал сайта), который отображает информацию об авторских правах и содержит динамически обновляемый год.

---

### Что тестируют эти тесты

#### 1. Рендеринг и структура

**`should render footer element`**
- **Проверяет:** Наличие элемента `<footer>` в DOM
- **Зачем:** Убедиться, что компонент корректно рендерится и имеет правильную семантическую структуру
- **Метод:** Поиск элемента по роли `contentinfo`, которая соответствует тегу `<footer>`

---

#### 2. Отображение контента

**`should display copyright text with current year`**
- **Проверяет:** Отображение текста с информацией об авторских правах и текущем годе
- **Зачем:** Подтвердить, что в футере корректно отображается динамический год и текст копирайта
- **Метод:** Проверка наличия текста с использованием текущей даты и регулярного выражения

---

#### 3. Динамическое обновление

**`should update year dynamically`**
- **Проверяет:** Корректное обновление года в тексте копирайта в зависимости от системной даты
- **Зачем:** Гарантировать, что год в футере всегда актуален и обновляется автоматически
- **Метод:**
  - Установка фиктивной даты с помощью `vi.useFakeTimers()`
  - Проверка точного соответствия текста с ожидаемым годом
  - Восстановление реальной системной даты

---

### Технические детали

- **Библиотеки:** React Testing Library, Vitest
- **Подход:** Мокание зависимостей (компонент `Container`) для изолированного тестирования
- **Управление временем:** Использование `vi.useFakeTimers()` и `vi.setSystemTime()` для тестирования динамических дат
- **Очистка:** Использование `beforeEach` и `afterEach` для сброса моков между тестами


## Тесты компонента Faq

### Общее описание

Данные тесты проверяют функциональность компонента **Faq** (Часто задаваемые вопросы), который реализует паттерн раскрывающихся панелей (disclosure) для отображения ответов на вопросы.

---

### Что тестируют эти тесты

#### 1. Корректность рендеринга

**`renders correct number of DisclosureButton components`**
- **Проверяет:** Отображение правильного количества кнопок с вопросами
- **Зачем:** Убедиться, что все элементы FAQ из источника данных отображаются на странице
- **Метод:** Поиск всех кнопок с текстом "Вопрос N" и подсчет их количества

**`renders all questions from content`**
- **Проверяет:** Отображение каждого конкретного вопроса из контента
- **Зачем:** Подтвердить, что данные из content.json правильно мапятся на UI
- **Метод:** Проверка наличия каждого вопроса по его тексту

---

#### 2. Интерактивность

**`expands and shows answer when button is clicked`**
- **Проверяет:** Раскрытие и отображение ответа при клике на кнопку вопроса
- **Зачем:** Основная функциональность компонента - показ/скрытие ответов
- **Метод:**
  - Подтверждение, что ответ изначально скрыт
  - Симуляция клика по кнопке
  - Проверка появления ответа

**`collapses and hides answer when button is clicked twice`**
- **Проверяет:** Скрытие ответа при повторном клике на кнопку
- **Зачем:** Обеспечение корректного переключения (toggle) состояния
- **Метод:**
  - Первый клик - ответ появляется
  - Второй клик - ответ скрывается
  - Проверка, что ответ больше не отображается

**`handles multiple independent disclosures`**
- **Проверяет:** Независимую работу каждого элемента FAQ
- **Зачем:** Критично для UX - открытие одного вопроса не должно закрывать другие
- **Метод:**
  - Открытие первого вопроса, проверка, что второй закрыт
  - Открытие второго вопроса, проверка, что первый остался открытым
  - Закрытие первого вопроса, проверка, что второй остается открытым

---

#### 3. Визуальная обратная связь

**`toggles chevron icon rotation when expanded/collapsed`**
- **Проверяет:** Вращение иконки-шеврона при переключении состояния
- **Зачем:** Предоставление визуальных подсказок пользователю о состоянии элемента
- **Метод:**
  - Проверка отсутствия класса `rotate-180` в начальном состоянии
  - Клик для раскрытия - проверка появления класса
  - Клик для закрытия - проверка исчезновения класса

---

### Технические детали

- **Библиотеки:** React Testing Library, userEvent, Vitest
- **Подход:** Мокание данных из `content.json` для изолированного тестирования
- **Асинхронность:** Все тесты взаимодействия используют `async/await` для корректной обработки событий
